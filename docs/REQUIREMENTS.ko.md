# Android 통합 문서 편집 앱 개발 프로젝트

## 1. AI의 역할

당신은 Android 네이티브 애플리케이션 개발, 문서 편집 엔진, 디지털 잉크 렌더링, 파일 포맷 호환성 및 모바일 UI/UX 설계에 전문성을 가진 시니어 Android 소프트웨어 엔지니어이자 소프트웨어 아키텍트입니다.

다음 요구사항을 충족하는 **안드로이드 전용 통합 문서 편집 및 필기 애플리케이션**을 설계하고 실제 개발하세요.

단순한 파일 뷰어, PDF 주석 도구, 파일 변환기 또는 UI 프로토타입이 아닌, 파일 형식별로 실질적인 편집 기능을 제공하는 앱이 목표입니다.

기능 버튼만 배치한 데모가 아니라 실제 파일을 불러오고, 수정하고, 저장하고, 다시 열 수 있는 작동 가능한 애플리케이션을 제작합니다.

# 2. 프로젝트 개요

## 2.1 프로젝트 목표

하나의 Android 앱에서 아래 응용프로그램의 주요 편집 기능을 통합합니다.

- Microsoft Word
- Microsoft Excel
- Microsoft PowerPoint
- 한컴오피스 한글
- PDF 전문 편집기
- 일반 텍스트 및 Markdown 편집기
- Goodnotes, Samsung Notes 등 디지털 필기 앱의 주요 필기 기능

사용자는 문서 파일을 선택하기만 하면 해당 확장자에 맞는 편집 화면으로 자동 진입해야 합니다.

예를 들어 DOCX를 열면 워드프로세서 편집 화면, XLSX를 열면 스프레드시트 편집 화면, PPTX를 열면 슬라이드 편집 화면이 표시되어야 합니다.

모든 문서 편집 화면에는 공통으로 펜·형광펜·자유 드로잉 기능을 제공합니다.

## 2.2 지원 플랫폼

- 운영체제: Android 전용
- 최소 지원: Android 10(API 29)을 기본 목표로 하되 필수 SDK의 호환성을 확인하여 최종 결정
- 스마트폰 지원
- 안드로이드 태블릿 지원
- 갤럭시 탭 지원
- S펜 지원
- 일반 정전식 스타일러스 지원
- 블루투스 키보드 지원
- 마우스 입력 지원
- 화면 회전 지원
- 분할 화면 및 멀티윈도우 대응
- 최종 배포 형식: APK 및 AAB

Windows, macOS, iOS, Electron 기반 데스크톱 프로그램은 개발 대상에서 제외합니다.

## 2.3 지원 파일 형식

다음 확장자를 필수 지원 대상으로 설정합니다.

| 유형 | 파일 확장자 |
|---|---|
| 텍스트 | .txt |
| Markdown | .md |
| PDF | .pdf |
| PDF/A | .pdf 파일 내부의 PDF/A 규격 |
| PowerPoint | .pptx, .ppt |
| 한글 | .hwp, .hwpx |
| Word | .docx, .doc |
| Excel | .xlsx, .xls |

PDF/A는 원칙적으로 별도의 파일 확장자가 아닌 PDF 보존 규격입니다.

확장자만으로 판단하지 말고 파일 내부의 MIME 정보, 헤더, 컨테이너 구조를 확인하세요.

잘못된 확장자, 암호화 파일, 손상된 파일에 대한 오류 처리도 구현합니다.

# 3. 기술 스택 및 시스템 구조

## 3.1 기본 개발 기술

아래 기술을 우선 검토합니다.

- 개발 언어: Kotlin
- UI: Jetpack Compose 및 Material 3
- 아키텍처: Clean Architecture + MVVM
- 비동기 처리: Kotlin Coroutines / Flow
- 의존성 주입: Hilt
- 앱 데이터베이스: Room
- 설정 저장: DataStore
- 파일 접근: Android Storage Access Framework
- 필기 렌더링: AndroidX Ink 또는 Canvas 기반 커스텀 엔진
- 대용량 처리: 메모리 효율적인 스트리밍 및 페이지 단위 로딩
- 호환성 처리: Android 네이티브 라이브러리, 적법한 서드파티 SDK 또는 NDK 모듈

위 기술은 권장안이며 실제 구현 가능성과 성능에 따라 변경할 수 있습니다.

## 3.2 문서 편집 엔진

각 문서 형식에 적합한 전용 편집 엔진을 사용합니다.

다음 기술들을 조사하고 비교하세요.

- AndroidX PDF
- AndroidX Ink
- PDFium 계열 라이브러리
- PDFBox Android 포트
- 상용 PDF 편집 SDK
- Microsoft Office 파일 호환 SDK
- ONLYOFFICE 통합 방식 및 라이선스
- Apache POI의 Android 호환성
- OOXML 처리 라이브러리
- HWP/HWPX 파서 및 공식 파일 포맷 명세

단순 파서와 실제 시각적 편집 엔진을 혼동하지 마세요.

서버 기반 오피스 편집 기술을 채택한다면 네트워크 연결이 필요한 기능을 반드시 구분해야 합니다.

**기본 원칙은 로컬 파일을 기기 내부에서 처리하는 오프라인 우선 앱입니다.**

클라우드 서버 없이 구현하기 어려운 기능은 기술적 이유와 비용을 명시하고 대안을 마련합니다.

모든 기능이 오프라인으로 작동한다고 허위 주장하지 않습니다.

## 3.3 모듈 구조

# 4. 안드로이드 앱 UI/UX

## 4.1 홈 화면

앱을 실행하면 다음 항목이 표시됩니다.

- 새 문서 만들기
- 파일 열기
- 최근 사용한 파일
- 즐겨찾기
- 파일 검색
- 최근 편집 문서
- 앱 설정

새 문서 만들기에서는 다음 형식을 선택할 수 있습니다.

- 일반 텍스트
- Markdown
- Word 문서
- 한글 문서
- Excel 스프레드시트
- PowerPoint 프레젠테이션
- PDF 문서

새 문서 생성 지원이 불가능한 형식은 선택하지 못하도록 하고 이유를 안내합니다.

## 4.2 파일 열기

안드로이드 기본 파일 선택기를 사용합니다.

- ACTION_OPEN_DOCUMENT
- ACTION_CREATE_DOCUMENT
- ACTION_OPEN_DOCUMENT_TREE(필요한 경우)
- ContentResolver
- DocumentFile

파일의 URI 권한을 적절히 관리하고 지속 가능한 URI 권한을 확보합니다.

다음 위치의 파일을 열 수 있도록 합니다.

- Downloads
- Documents
- 기기 내부 저장소
- SD 카드
- Android 파일 선택기에 연결된 문서 제공자
- Google Drive 등 사용자가 접근을 허용한 파일 제공자

앱 전체 저장소 접근 권한을 불필요하게 요구하지 않습니다.

다른 앱의 공유 메뉴에서 '이 앱으로 열기'를 선택할 수도 있어야 합니다.

ACTION_VIEW 및 ACTION_SEND 인텐트를 지원합니다.

## 4.3 편집 화면

상단에는 다음 요소를 배치합니다.

- 뒤로 가기
- 파일명
- 수정 상태
- 실행 취소
- 다시 실행
- 저장
- 메뉴

문서 종류에 따라 편집 도구를 동적으로 변경합니다.

예시:

Word: 글꼴 / 문단 / 삽입 / 레이아웃 / 검토 / 그리기

Excel: 홈 / 수식 / 데이터 / 삽입 / 보기 / 그리기

PowerPoint: 홈 / 슬라이드 / 삽입 / 애니메이션 / 전환 / 그리기

PDF: 페이지 / 편집 / 주석 / 그리기 / 변환

TXT·MD: 텍스트 / 검색 / 보기 / 그리기

## 4.4 스마트폰 UI

스마트폰에서는 좁은 화면을 고려합니다.

- 하단 도구 모음
- 접을 수 있는 편집 메뉴
- Bottom Sheet 기반 서식 설정
- 화면을 가리지 않는 키보드 처리
- 한 손 조작을 고려한 주요 버튼 배치
- 도구 모음 가로 스크롤
- 터치하기 쉬운 버튼 크기

## 4.5 태블릿 UI

태블릿에서는 넓은 화면을 활용합니다.

- 상단 확장형 도구 모음
- 좌측 페이지·슬라이드·시트 패널
- 중앙 문서 편집 영역
- 우측 속성 패널
- 여러 문서 탭
- 분할 화면
- 펜 도구 고정 표시
- 가로·세로 모드 최적화

화면 크기와 창 크기에 따라 적응형 레이아웃을 적용합니다.

# 12. 파일별 필기 저장 구조

필기는 문서를 닫았다가 다시 열어도 유지되어야 합니다.

## PDF

가능하면 PDF 표준 Ink Annotation으로 저장합니다.

## Word

가능한 범위에서 DOCX 내 그림·도형·잉크 표현으로 저장합니다.

직접 저장이 불가능한 경우 원본을 보호하고 별도의 주석 데이터를 유지합니다.

## PowerPoint

슬라이드 좌표에 연결되는 드로잉 개체 또는 주석으로 저장합니다.

## Excel

시트와 셀 좌표를 기준으로 드로잉 위치를 관리합니다.

스크롤과 확대·축소에 따라 필기 위치가 정확히 유지되도록 합니다.

## HWP/HWPX

지원되는 개체 모델과 호환성에 따라 필기를 포함하고, 불가능한 경우 외부 주석 레이어를 사용합니다.

## TXT/MD

파일 형식 자체가 자유 필기를 포함하지 않으므로 원본과 분리된 주석 데이터로 저장합니다.

### 공통 원칙

- 저장 후 필기 유지
- 문서 재열기 후 위치 유지
- 파일별 독립된 필기 데이터
- 문서 삭제 시 관련 필기 처리 정책
- PDF 등으로 필기 포함 내보내기
- 주석 데이터 백업
- 필기 정보 손실 경고

필기 데이터를 원본에 직접 내장한 것인지, 별도 파일에 저장한 것인지 사용자에게 명확히 표시합니다.
