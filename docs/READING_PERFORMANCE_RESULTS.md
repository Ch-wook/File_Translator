# 문서 스튜디오 읽기 화면 및 성능 점검

기준: 0.8.8-preview 원격 작업 코드 `3a56a4b3e14e56ee17988fb2688556a1d7e40e69`.
이전 미푸시 0.8.0 소스를 복구한 결과가 아닙니다. 현재 실행 환경이 연결되지 않아 GitHub 원격 코드와 Actions로 작업했습니다.

## 발견한 원인과 수정

| 경로 | 확인한 문제 | 수정 |
|---|---|---|
| 일반 읽기 화면 | 읽기 중 undo/redo/save 자리와 하단 48dp 보기 도구가 계속 표시됨 | 한 줄 헤더에 검색·편집·더보기; 세부 보기 도구는 필요할 때 표시 |
| Office 호스트 | 로드 후에도 200ms마다 도구 상태/DOM/파트 목록 갱신 | 로드 확인 폴링 종료, 엔진 이벤트를 프레임당 한 번으로 묶음; 같은 속성·문자열 재기록 차단 |
| Office 위치 보존 | 맵 이벤트가 없는 레이아웃 이동도 존재 | 위치 좌표 보정용 1초 샘플러 유지; 숨긴 문서에서는 실행하지 않음; 문서 전체 파싱이나 도구 재구성 없음 |
| 한글 호스트 | 연속 엔진 이벤트마다 즉시 도구 상태 갱신 | 프레임 단위 병합; 기존 편집 보호·IME·안전한 저장 유지 |
| 포커스 | 같은 문서를 터치해도 select→flush 경로 실행 | 활성 문서는 문서 전환/복구 저장 요청 생략; 입력 취소 그룹 구분 유지 |
| 복구 저장 | 작업 전/후 최근 목록 중복 읽기; 닫을 때 중복 체크포인트 | 작업당 최근 목록 갱신 통합; 체크포인트 직렬화 락; 동일 디스크 상태는 fsync·목록 쓰기 생략; 약한 참조 4개 한도의 캐시를 inode·나노초 수정 시각·크기로 검증하여 반복 JSON 생성도 생략 |
| 재열기 | 원본 바이트가 같아도 기존 모델 파싱 뒤 기준 파일 재복사와 재파싱 | 원본 해시·형식 일치를 확인한 경우 복원한 모델 재사용 |
| 큰 파일 복사 | readBytes로 전체 배열을 만든 뒤 작업 파일 쓰기 | AtomicFile에 64KiB 스트리밍 복사; 원본/작업 파일 분리 유지 |
| PDF | 읽기 중 편집용 문자열·이미지 목록 분석; 초기 읽기 효과에서 중복 렌더링 | 읽기는 페이지 렌더만; 편집 진입 시 메타데이터 준비; 모드 전환만으로 기존 비트맵 재생성 방지 |
| PDF 크기 조회 | 크기를 구하려고 PDFBox로 전체 문서 로드 | PdfRenderer의 회전·CropBox가 반영된 페이지 크기 사용 |
| TXT | readOnly에서 포커스를 매번 해제하여 선택·복사가 불편함 | 선택 가능한 실제 TextView 읽기 상태, 입력 차단; 같은 보기 크기·줄바꿈 반복 설정 제거 |
| 줄 번호 | 매 입력마다 문서 전체 문자에서 줄 시작점을 다시 검색 | 편집 구간의 줄바꿈만 검색하고 기존 시작점을 이동 |
| 폴더 검색 | 검색어가 바뀔 때마다 SAF 폴더를 다시 조회 | 성공한 폴더 목록을 5초·8폴더·총 2,000항목 한도로 재사용; 취소·만료·새로고침 유지 |
| 최근 파일 | 화면 상태 변경 시 목록 필터와 날짜 객체 재생성 | 조건별 필터 결과와 날짜 표시 재사용 |
| 저장 실패 | 일반 작업 실패가 기존 문서를 ERROR 상태로 바꾸어 편집이 막힘 | 실제 로딩 실패와 저장 실패 구분; 최신 복구본·편집·재시도 유지 |

외부 원본 저장의 충돌 검사·백업·해시 readback·실패 복원은 제거하지 않았습니다.
변경 없는 문서의 네이티브 원본 저장 차단은 기존 기능으로 유지했습니다. 추가로 실제 편집을 한 번도 허용하지 않은 정상 로드 Office 읽기 세션은 작업 파일 해시를 봉인한 후 해당 전용 프로세스를 종료하여 네이티브 BYE 정리를 기다리지 않습니다. 편집 허용 이력·미저장 변경·저장 작업·PDF 변환 작업·로드 오류가 있으면 기존 저장 확인과 네이티브 종료 경로를 유지합니다.

## 형식별 화면과 유지 기능

| 형식 | 이번 변경 | 유지/제한 |
|---|---|---|
| DOCX/DOC | 읽기 전용 검색·전체 화면, 기존 위치 유지, 갱신 병합 | 실제 Collabora 문서 모델·선택 서식·저장 유지; 모바일 재배치 읽기 모드는 새로 구현하지 않음 |
| XLSX/XLS | 같은 읽기 헤더와 전체 화면, 셀/시트 맥락 유지 | 기존 타일 기반 실제 Calc, 수식·셀 서식·시트 유지; 대형 파일 첫 파싱 생략 안 함 |
| PPTX/PPT | 읽기 전체 화면·검색, 기존 슬라이드 목록 유지 | 실제 슬라이드 엔진·개체/서식/순서 유지; 새로운 썸네일 캐시나 가로 스와이프 엔진은 구현하지 않음 |
| HWPX/HWP | 빠른 도구 상태 갱신, 읽기 검색·전체 화면 | 원본 페이지·표·그림·서명·자간/장평, 실제 읽기 전용, 기존 viewport 복원과 PDF 변환 유지 |
| PDF | 편집 데이터 지연 준비, 한 캔버스 모드 전환, 너비/페이지 맞춤, 페이지 이동, 선택 가능한 페이지 텍스트, 읽던 페이지/확대 저장, 선택적 연속 보기 | 기본 페이지 캔버스 유지; 연속 보기는 보이는 페이지만 비트맵 보유; 화면 확대와 실제 문서 서식 분리 |
| MD | 서식 있는 읽기 화면 기본, 원문 보기·편집 분리, 표 가로 스크롤·코드 가독성·어두운 보기 | 네트워크 자동 요청 없음; 원격/로컬 이미지 새 로더 미구현; 외부 링크는 사용자의 탭으로 브라우저 연결 |
| TXT | 선택/복사, 검색 전용 상태, 글꼴/크기/줄 번호/줄바꿈/어두운 보기, 스크롤 복원 | 표시 설정이 파일 바이트·인코딩을 바꾸지 않음 |

전체 화면 자동 전환은 문서의 빈 여백에서 짧게 탭했을 때만 처리합니다. 텍스트 링크·셀·선택 처리를 맡는 실제 문서 canvas/img/svg에는 자동 전환을 적용하지 않습니다. 전체 화면 메뉴는 계속 사용할 수 있습니다. 드래그·긴 누르기·여러 포인터·기존 선택·링크·도구 클릭은 제외하고 메뉴 표시 버튼으로 복귀할 수 있습니다. 자동 스크롤에 의한 메뉴 숨김은 추가하지 않았습니다.

자필 서명·파일 변환의 엔진이나 손실 정책을 교체하지 않았습니다. 한글→PDF는 기존 전체 페이지 이미지 방식으로, 검색 가능한 텍스트/링크를 보존하는 변환으로 표시하지 않습니다.

## 검증 상태

측정 및 최종 회귀 실행 중입니다. 아래의 수치는 실행 결과가 확보된 뒤 채웁니다. 이 문서 초안은 테스트 완료 보고가 아닙니다.

- 비교 기준: 동일 GitHub Actions 실행의 같은 Android 35 x86_64 Pixel 7 프로필 에뮬레이터, SwiftShader, RAM 3,072MiB.
- 기준 앱과 후보 앱을 순서대로 새로 설치합니다. 물리 휴대폰 측정이 아닙니다.
- 저장/열기: 한글·영문 5,000줄 TXT, 복구 체크포인트 20회, 원본 무변경 저장 5회.
- PDF: 80페이지 크기 조회 20회, 렌더 3회; 별도 UI에서 41페이지 이동→연속 목록 61페이지→홈→재열기.
- 네이티브 보기: 기본 DOCX/XLSX/PPTX/HWPX 각 1회. 준비·엔진 ready·2초 동안 헤더 DOM 변동·변경 없는 닫기와 프로세스 PSS를 기록합니다.
- TXT 모드/메뉴 시간 5회는 Compose 테스트의 동기화 비용을 포함합니다. 원시 입력 지연으로 해석하면 안 됩니다.
- Activity 시작 TotalTime은 3회 기록하며, 홈 데이터가 모두 보이는 시간 또는 기기 콜드 부팅 시간과 동일하지 않습니다.
- Android 실제 입력/서식/구조 저장·재열기, 서명·변환, JS 권한, TypeScript, 독립 문서 파서, 설치 보존을 함께 검증합니다.

## 아직 검증하지 않았거나 추가 작업이 필요한 부분

실제 ARM64 휴대폰, 삼성/Gboard 조합·S펜, 실제 저장 장치/클라우드 SAF 제공자 지연, 60fps·입력 100ms 보장, 장시간 배터리와 최대 메모리, 대형 실제 회사 문서/수식/슬라이드의 성능은 별도 실기기 검증이 필요합니다. 읽기 전용 종료의 과정별 시간을 실제로 비교하며, 중간 후보에서 관측한 종료 지연 악화를 최종 결과로 숨기지 않습니다. 개별 기본 파일 1회로 모든 문서의 열기/닫기 속도 향상을 단정하지 않습니다.

Word 재배치 읽기·제목 탐색, PPT 썸네일 선행 준비·스와이프, 확대 배율별 PDF 고해상도 재렌더, 연속 보기의 픽셀 단위 위치 복원, 모든 형식 공통 확대/페이지 정보 UI, 변환기의 전후 속도 비교는 완료 범위에 포함하지 않습니다.

원본 안전성을 위해 필요한 형식 검증, 저장 후 재읽기·해시 비교, 충돌 검사는 성능을 이유로 생략하지 않았습니다. 캐시는 문서 복구본을 삭제하지 않습니다.

## 배포

확인된 APK·소스·검증 자료를 준비한 뒤 최종 커밋과 다운로드 해시를 기록합니다. 기존 0.8.8 서명키를 사용할 수 없어 사용자 선택에 따라 별도 `kr.documentstudio.readingpreview` 앱을 사용합니다. 기존 앱과 내부 복구본을 삭제하지 마세요. 자동 이관은 하지 않으며 기존 앱에서 저장한 문서를 새 앱으로 열 수 있습니다.
