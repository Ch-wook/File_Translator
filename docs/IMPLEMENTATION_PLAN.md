# 전체 기능 검증·보완 계획서

작성일: 2026-10-16. 기준 커밋: `5a98995`. 기준 문서: [원문 요구사항](REQUIREMENTS.ko.md). 이 계획을 먼저 기록한 뒤 코드 변경과 검증을 진행한다.

## 목표와 완료 판정

버튼 유무나 예외 없이 실행되는 것만으로 완료를 판정하지 않는다. 사용자가 **열기 → 실제 내용 수정 → 실행 취소/다시 실행 → 저장 → 닫기 → 재열기**를 수행하고 수정 결과가 파일에 남는지 확인한다. 필기는 본문 편집과 별도로 저장·복구·위치를 검사한다. 지원하지 않는 동작은 원본을 바꾸기 전에 이유를 안내해야 한다.

원문 §17·§20은 모든 전문 기능의 단기 완성을 전제하지 않으며 기술적 제약과 대안을 명시하도록 요구한다. 따라서 다음 상태를 구분한다.

- **검증**: 자동 검사 또는 재현 가능한 수동 절차와 결과가 있다. 테스트한 입력과 환경 안에서의 통과다.
- **구현/미검증**: 실행 코드가 있으나 해당 기능의 독립적인 검사가 부족하다.
- **제한**: 일부 입력만 지원하며 거부 조건과 대안이 있다.
- **미지원**: 실행 가능한 구현이 없다. 완료 수에 포함하지 않는다.
- **외부 검증 필요**: 실기기·외부 프로그램·표준 검증기 등이 필요하다. 에뮬레이터나 XML 검사로 대체해 통과시키지 않는다.

## 검사 방법

1. **순수 엔진 검사**: JVM에서 실제 DOCX/XLSX/PPTX/HWPX/HWP/DOC/XLS/PPT를 생성·수정·재열기한다. OOXML은 Apache POI, HWPX는 별도 hwpxlib로 확인한다. 이 결과는 Microsoft/한컴 프로그램에서의 시각적 호환성 인증이 아니다.
2. **저장·복구 통합 검사**: Android ContentProvider로 정상·충돌·쓰기 실패를 재현하고 저장된 바이트를 검사한다. ZIP은 복원 후 다시 내보내어 편집과 복구 자료가 남는지 확인한다.
3. **화면 검사**: Compose/Android View의 실제 입력·다이얼로그·키보드·인텐트·재생성을 사용한다. 모델만 변경한 검사를 UI 검사로 세지 않는다.
4. **파일별 순환 검사**: 열기/편집/원본 형식 저장/재열기/필기 보존을 각각 assert한다. 외부 앱 검증과 실제 장치가 필요한 항목은 별도 열에 기록한다.
5. **최종 게이트**: JVM/Android 검사 실패·오류·건너뛰기 0, lint 오류 0, debug APK 빌드 성공, diff 점검, 원격 push 확인. 경고·범위 제한은 숨기지 않는다.

검증 환경은 기존 API 35 에뮬레이터를 사용한다. 실제 Galaxy Tab/S펜·블루투스 장치, API 29/36/37·16 KB 기기, 외부 Office/한컴·PDF/A 표준 인증은 별도 확보가 필요하다. 해당 조건이 충족되지 않으면 최종 기록에서도 미검증 상태를 유지한다.

## 진행 기록

- 계획 작성: 원문 §1–§21과 기존 지원표·검사 결과·저장/화면 코드를 읽고 위 순서를 확정했다. 코드 보완 전 계획서를 생성했다.
- 단계 1: F01–F24 아래 세부 기능을 [인수 확인표](FEATURE_ACCEPTANCE.md)에 연결했다. 기존 지원 기능·내장 엔진 경로·기능별 미검증·미지원을 분리했다. 기존 검사는 107개였으며 메뉴만 있는 전문 기능을 통과로 합산하지 않았다.
- 단계 2: 복원 ZIP의 보존 자료 누락과 처리 중 외부 인텐트 무시를 고쳤다. ZIP 격리/재백업/충돌 보존·경로/용량 한도, 프로세스 공용 인덱스 잠금, 외부 열기 대기열·URI 권한을 구현했다. 동시 생성 12개·반복 백업/복원·VIEW/SEND·기존 입력 보존을 검사했다.
- 단계 3: HWPX 표 생성/행열/병합/분할/크기/셀 서식과 위치 라벨, 16개 함수 검색/완성, PDF 직접 이미지 위치/크기/삭제를 추가했다. 보호된 구조·지원하지 않는 이미지 상태는 거부한다. HWPX는 별도 hwpxlib, OOXML은 POI, PDF는 내용 스트림/실제 렌더 픽셀로 확인했다. 숫자 슬라이드 변환이 그림을 누락하던 순번 처리도 고쳤다.
- 단계 4: 필기의 반복 전체 복사와 그리기 임시 객체를 줄이고 역사 샘플별 기울기를 보존했다. 완료 획 불변성·도구 렌더, 슬라이드 이미지 수명/Undo/재생성, 합계 800만 화소 제한과 해제를 검사했다. 휴대폰 키보드와 함수 완성/셀 표, 태블릿의 HWPX 표 입력/실제 SAF 저장을 수동 확인했다. 저장 파일의 3×3 표/첫 셀 `TABLE_OK`도 확인했다.
- 단계 5: 반복 검증 스크립트를 추가해 최종 코드에서 **JVM 71 + Android 60 = 131개 통과, 실패·오류·건너뛰기 0, lint 오류 0/경고 22, debug APK 빌드 성공**을 확인했다. 직전 29개 경고 중 DrawAllocation 7개가 사라졌으며 실제 필기 지연 인증과 구분했다. 근거는 `artifacts/acceptance-20261016-180215/`에 보관한다. 기능별 결과·지원표·설계·사용/빌드 안내·원문 연결을 갱신했다. GitHub `main` 반영 버전은 해당 변경 커밋과 원격 브랜치 기록으로 추적한다.

## 잔여 요구사항과 판정 한계

자동 게이트는 지원되는 편집 흐름의 회귀 검사다. 원문의 전문 기능 전체가 완성되었다는 판정이 아니다. 한글 전문 조판/고급 개체/변환, 셀·본문 재배치에 부착되는 공통 필기, OCR·손글씨 변환, PDF/A 적합성, 동시 분할 문서, 보정/즐겨찾는 펜 도구 등의 미지원과 내장 오피스 전문 메뉴별 미검증을 확인표에 남겼다. 실제 Galaxy/S펜·외부 Office/한컴·API별/16 KB 기기·성능/접근성 인증은 수행하지 않았다. 이 항목은 필요한 실행 환경·엔진·검증 자료를 확보해 별도로 통과 근거를 추가해야 한다.
