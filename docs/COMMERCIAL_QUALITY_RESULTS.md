## 2. 실제 수정 사항

### 저장·복구

외부 파일을 변경하기 전에 앱 내부 provider-recovery에 원본, 최신 출력, SHA-256, 대상 URI, 저장 단계를 기록한다. 앱 내 Mutex와 프로세스 간 파일 잠금으로 저장 준비·쓰기·검증을 직렬화한다. 종료된 저장의 백업은 다음 시도로 대체하지 않는다. 외부 파일이 최신 결과와 일치하면 다시 쓰지 않고 확인할 수 있다. 앱 체크포인트 완료 뒤에만 해당 저널을 완료 처리한다.

저장 중단·실패 자료는 홈/설정의 **저장 복구**에서 이전 원본과 최신 편집본을 각각 새 파일로 꺼낼 수 있다. 복구 내보내기로 원본을 자동 덮어쓰지 않는다. 복구 삭제는 확인 후 선택한 내부 기록만 지우며 외부 문서는 삭제하지 않는다. 해시가 맞지 않거나 해석하지 못하는 기록은 자동 삭제하지 않는다.

SAF 제공자의 readback은 현재 읽히는 바이트 확인이다. 모든 제공자의 원자적 파일 교체, 외부 앱과의 compare-and-swap, 원격 클라우드 영구 반영까지 증명하지 않는다. 성공한 쓰기의 readback이 예상과 다르면 외부 변경일 가능성이 있어 무조건 롤백하지 않는다. 원본과 사본을 보존해 비교해야 한다. 전원 차단·모든 클라우드 제공자·저장 공간 고갈 전 범위를 검증한 결과가 아니다.

### 서명

실제 PNG의 헤더·끝·디코딩·치수, 목록 수, 고유 ID, 획 수·좌표·압력·굵기를 제한한다. 손상 보관함을 빈 목록으로 바꾸지 않고 기존 자료와 이전 정상본을 보존한다. 확인 후 이전 보관함 복원과 개인정보를 포함하는 서명 복구 ZIP 내보내기를 제공한다. 보관 실패 시 표시 목록도 유지한다.

기존 자필 PNG 삽입·이동·크기 조절·표 셀 내 삽입·HWP/HWPX 저장·PDF 연동을 유지한다. 인증서 기반 전자서명이 아니며 문서 위 편집 가능한 벡터 필기 전체가 새로 구현된 것은 아니다.

### UI·오류·개인정보

- 기존 보기/편집 구분, 한 줄 상단과 형식별 하단 도구를 유지한다.
- 시스템 어두운 색상은 도구와 TXT/Markdown 읽기에 반영한다. 문서 원본의 용지·글자색은 바꾸지 않는다.
- 홈은 화면 폭·글자 배율에 따라 카드 수를 조정한다. 최근 문서 정렬, 이름 검색, 즐겨찾기, 숨김 목록과 복원을 제공한다. 목록 숨김으로 파일·복구본을 지우지 않는다.
- 첫 안내는 닫으면 다시 표시하지 않는다.
- 변환 결과가 미저장이면 교체·종료를 확인한다. 실제 기록·검증 중에는 중복 요청·취소를 제한한다.
- 오류 원문·문서명·경로를 보여주지 않는다. 로컬 진단에는 오류 분류·시각·앱/API 버전·엔진 구분만 기록한다. 외부 오류 수집 서비스를 새로 도입하지 않았다.

앱은 문서·서명·변환 결과를 서버로 전송하는 기능과 INTERNET 권한을 사용하지 않는다. OCR은 번들 Google ML Kit다. 이 권한 검사만으로 Google Play 서비스 IPC·SDK·운영체제 전체에서 통계 처리가 전혀 없다고 단정하지 않는다. 계약·정책 검토와 네트워크/IPC 실측이 추가로 필요하다.

앱 내부 자료는 OS 앱 저장소에 보관하며 전체를 별도 암호화하지 않는다. 선택한 .dsbackup 내보내기만 기존 AES-256-GCM을 사용한다. 앱 삭제·데이터 삭제는 복구본과 내 서명을 지운다. 외부에 저장·공유한 파일은 별도로 관리해야 한다.

## 6. 남은 위험과 상용 출시 조건

1. 실제 ARM64 휴대폰의 설치·외부 저장 제공자·한글 IME·S펜·회전/복귀·장시간 사용·저장 공간 부족 검증.
2. TalkBack, 접근성 스캐너, 고대비·대형 글자·가로/태블릿 전 화면 검토.
3. 안정된 운영 서명키와 안전한 CI 비밀, 배포 계정·정식 Release/AAB·업데이트 경로. 현재 별도 프리뷰는 기존 앱을 덮어쓰지 않는다. 미제공 운영 키/스토어 작업을 완료했다고 주장하지 않는다.
4. PDFBox Android 2.0.27 포트의 보안 검토, 악성 문서 코퍼스·ANR/메모리·격리 처리, native/Wasm/전이 라이선스·공급망 감사.
5. 전원 차단, 동시에 수정하는 외부 앱, 모든 클라우드 제공자의 저장/복원, 손상 저널의 수동 회수 범위.
6. Google ML Kit/운영체제 개인정보 동작, 정식 개인정보처리방침·연락처·보관/삭제 정책과 법무 검토.
7. 필드 충돌·ANR 모니터링, 스크롤 프레임/터치 첫 프레임·최대 메모리/배터리 수집. 현재 로컬 분류 기록은 전체 운영 모니터링을 대신하지 않는다.
8. 고급 문서 요소·변환·OCR·일괄 작업과 일부 화면의 어두운 모드 세부 검토.

위 항목을 남긴 상태를 상용 서비스 완성으로 표시하지 않는다. 이번 배포는 기존 엔진을 유지하고 재현한 데이터 위험을 고친 품질 개선 프리뷰다.

## 보안 검사 후 추가 수정

157개 release Maven 좌표 조회에서 Log4j API 2.24.3의 GHSA-qv9r-c865-cp47 / CVE-2026-49844가 일치했습니다. 공개 권고의 수정 버전 2.25.5를 고정하고 NaN·Infinity·-Infinity의 JSON 출력 재현 검사를 추가합니다. 이전 검사에서 일치가 0개였다고 보고하지 않으며, 갱신된 의존성·APK·회귀 검사를 다시 실행합니다. [공개 권고](https://github.com/advisories/GHSA-qv9r-c865-cp47). 

추가 보안 수정 이후 provider readback의 크기 상한과 저장 공간 부족(ENOSPC) 안내 우선순위도 보완했습니다. 최종 회귀에는 Log4j JSON 재현 1건과 저장 공간 안내 1건을 추가하며 전체 단위 검사의 실제 합계를 결과로 확인합니다.

최근 목록의 정렬 시각은 앱 작업 기록 기준입니다. 외부 원본의 마지막 수정 시각을 전부 조회해 표시하는 기능은 추가 확인 대상입니다. 새로운 Log4j 재현 테스트에서 put의 문자열 API에 숫자를 전달한 컴파일 오류를 바로잡아 with의 실제 숫자 API로 재실행하며, 컴파일 실패를 테스트 통과에 포함하지 않습니다.
