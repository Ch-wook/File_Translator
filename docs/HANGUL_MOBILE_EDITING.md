# 모바일 한글 편집 0.8.3-preview

기존 Android 앱·Rhwp 0.8.7·Collabora·PDF 엔진과 원본 보기 화면을 유지한 단계적 개선이다. 구조 있는 문서를 텍스트 입력창으로 대체하지 않는다. 이전 환경의 미푸시 aa3be049 소스는 회수하지 못했으며, 원격 2bfe225에서 재구현한 0.8.2에 이어 작업했다.

## 설치와 원본 보호

- 앱 이름: **문서 스튜디오 모바일**, applicationId: **kr.documentstudio.mobilepreview**, versionCode 13.
- 사용자 요청에 따라 기존 0.8.2와 병행 설치한다. 이전 앱·데이터 삭제가 필요하지 않다. 이전 서명키를 복구한 업데이트가 아니다.
- Android 10 이상 64비트 ARM64 휴대폰용 APK와 x86_64용 APK를 따로 제공한다. Office 엔진은 Android 11 이상이다.
- 개발 서명 프리뷰이다. 영구 서명키를 채팅·소스·Release·캐시에 넣지 않는다. 다음 동일 앱 업데이트에는 같은 비공개 키가 필요하다.
- 파일은 먼저 **보기**로 연다. **편집하기**를 선택해야 입력·서식·구조 변경이 가능하다.
- 입력이 멈춘 뒤 약 1.2초 후 작업 복사본을 저장한다. 한글 조합 중에는 저장을 미루고, 저장 중 새 변경이 생기면 최신 상태를 다시 저장한다.
- 원본 파일 반영은 **저장 후 닫기**와 기존 앱 저장 경로를 따른다. 읽기만 하고 닫을 때는 내보내지 않는다.
- 엔진 보존 보고에 손실이 있으면 저장을 중단한다. 작업 파일은 임시 파일 검증·원자적 교체·편집 표시·종료 표시·기존 충돌/복구 경로를 사용한다.
- 전원 종료 직전 등 마지막 체크포인트 이전 입력까지 보장하지 않는다. 저장 상태 표시를 확인한다. 실행 취소 이력은 현재 편집 세션에 한정한다.

## 모바일 조작

보기에서 편집하기를 선택하면 문서 아래에 기존 색상을 유지한 도구가 나타난다. 글자/문단/목록/표/그림/삽입/찾기/스타일/쪽/클립보드 탭을 가로로 이동할 수 있다. 상세 설정은 화면 일부만 차지하는 스크롤 패널이며, 표/개체를 선택하면 관련 도구로 전환한다. 표 안에서도 글자 탭으로 서식을 변경할 수 있다.

도구 버튼은 최소 44px이다. 도구를 누를 때 불필요한 입력 포커스 이동을 막고, 숫자 필드를 편집하는 동안에는 문서의 선택 토큰을 보관한다. 선택이 없으면 적용 범위에 **커서 이후 입력**을 표시한다. 설정 완료로 문서 입력에 돌아간다. 지원 조건이 맞지 않는 기존 엔진 명령은 비활성화한다.

## 검증 기준과 남은 범위

최종 배포는 실제 엔진 브라우저 HWP/HWPX 시나리오와 hwplib/hwpxlib 독립 파서, Android 실제 InputConnection 기반 테스트 IME, 기존 P0 19건을 포함하는 총 21건의 실제 성공을 요구한다. ABI별 APK의 인증서 일치, testOnly 없음, INTERNET 권한 없음, 16KiB ELF/APK 정렬, 검사한 엔진 자산과 APK 자산 일치, 기존 0.8.2 병행 설치·데이터 보존·재설치도 별도로 확인한다.

실행 환경 장애 때문에 로컬 셸·물리 휴대폰에 접근할 수 없다. 코드는 GitHub API로 보존하고 GitHub Actions에서 빌드·실행한다. Chromium의 휴대폰 화면은 Android 기기 검증과 구분하며, x86_64 Android 에뮬레이터의 테스트 IME는 실제 삼성 키보드/Gboard 또는 ARM64 휴대폰 검증을 대신하지 않는다.

실제 실행 결과와 Release 링크는 검증 완료 후 아래에 추가한다. 통과하지 않은 검사를 통과로 표시하지 않는다.


### 편집 회귀 수정

선택 범위를 조합/직접 입력으로 교체할 때 삭제와 새 입력을 하나의 기존 엔진 이력으로 묶었다. 화살표는 먼저 선택 시작/끝으로 접고 다음 글자를 건너뛰지 않는다. 표의 행·열이 바뀌면 유효한 셀로 커서를 옮긴 후 도구 상태를 알리며, 셀 서식 명령은 기존 flat 위치에도 정규 셀 경로를 구성한다. 실패한 표 명령은 호스트에 오류를 전달한다.

변경 패치 기준은 0.8.2의 `244b94507d8bda5dbf248877f17ed88b745035f2`이며 과거 미복구 d87a441 패치와 구분한다.

### HWP 개체 헤더 호환성

새 표를 포함한 HWP의 42바이트 CTRL_HEADER에서 hwplib 1.1.10이 생략된 선택 속성을 무조건 읽어 다음 레코드까지 소비하는 문제를 재현했다. hwplib upstream의 [#315 수정 커밋](https://github.com/neolord0/hwplib/commit/877c78af2f327f84b8a07e1691fe3c79d53b43d0)에 해당한다. Maven 1.1.11은 이 수정 이틀 전에 배포됐으므로, 1.1.11 JAR의 해당 클래스 한 개를 공식 수정 소스로 교체한다. [출처·포장 방식·경계 검사](HWPLIB_READER_PATCH.md)를 기록했다. 파서 예외를 무시하거나 문서를 텍스트로 재생성하지 않는다. 수정 후 실제 엔진의 HWP/HWPX 출력에 대해 부분 서식·표 구조/내용·정확한 PNG 바이트를 독립 파서로 다시 검사한다.

길게 누르기는 개체용 더블클릭 대신 기존 엔진의 단어 경계와 실제 본문/셀 커서를 사용하도록 수정했다.

### 표 개체가 있는 문단의 줄바꿈

기존 문단의 끝에서 줄바꿈할 때 마지막 글자 앞이 분할되는 경우를 실제 저장 XML로 재현했다. 커서는 글자 위치를 사용하지만 엔진 문단 분할은 이동 가능한 표·그림·도형·수식·각주/미주·번호 개체의 자리까지 센 논리 위치를 받았다. JS/WASM 경계에서 엔진의 실제 개체 위치와 종류를 사용해 변환한다. 키보드 Enter와 multiline 붙여넣기, undo/redo 후 기존 문단의 모든 글자가 유지되는지 즉시 검사하고 저장 후 독립 파서 검사도 유지한다.
