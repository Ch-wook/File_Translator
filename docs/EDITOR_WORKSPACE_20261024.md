# 문서·개체 편집 작업 공간 개선

대상: `codex/editor-workspace` 작업 브랜치. 기존 v0.6.0 릴리스의 검증 기록과 구분한다.

## 문제와 변경

기존 오피스 진입은 모바일 엔진의 읽기 모드로 시작했다. 실제 편집 기능이 있어도 연필 버튼을 다시 눌러야 했으며, 기본 화면의 런 입력은 개체 편집과 다른 작업 방식이었다. 기본 슬라이드는 드래그 중 선택 테두리만 움직였고, 놓으면 선택이 풀렸으며 크기·회전 핸들이 없었다. 기본 문서 입력은 여러 줄을 받으면서 패키지 저장에서는 줄바꿈을 거부했다.

- Word·Excel·PowerPoint의 **실제 엔진이 로드를 완료하면 편집 모드로 한 번 진입**한다. 이후 사용자가 읽기 모드로 나가면 자동으로 다시 편집을 강제하지 않는다. 실제 읽기 전용 진입에는 적용하지 않는다.
- 엔진 위에 `홈 / 삽입 / 개체` 도구를 배치한다. Excel에는 `셀`, PowerPoint에는 `슬라이드` 탭을 추가한다. 가로 스크롤·접기·명령 비활성화·선택 상태·화면 높이 대응을 제공한다.
- 개체 탭은 선택·이동, 위치·크기, 앞뒤 순서, 정렬, 뒤집기를 실제 엔진 명령으로 수행한다. 개체가 선택되기 전에는 관련 명령을 비활성화한다.
- Word의 `자유 배치`는 선택한 그림·도형의 문단 앵커와 텍스트 배치를 바꾼다. 일반 본문을 자유 도형으로 바꾸는 기능은 아니다.
- Excel의 셀·범위 선택, 입력, 행·열 크기, 개체 조작은 실제 Calc 편집기에서 수행한다. 복사·잘라내기·붙여넣기는 기존 네이티브 클립보드 경로를 사용한다.
- 기본 작업 화면에는 모든 도구 탭에서 접근할 수 있는 `편집기 열기`를 둔다. 손필기와 기본 편집을 마친 뒤 실제 엔진으로 돌아갈 수 있다.
- 기본 PowerPoint 캔버스는 개체 선택을 유지하고 실제 도형·그림을 움직이는 미리보기, 모서리 크기 조절, 회전 핸들, 앞뒤 순서·삭제를 제공한다. 회전한 개체도 실제 회전 영역에서 선택한다. 취소한 제스처는 저장 명령을 만들지 않는다.
- 기본 DOCX/HWPX는 같은 문단의 여러 런을 하나의 입력 영역에 표시한다. 입력 변화만 원래 런에 나눠 적용해 기존 서식을 유지한다. 선택 범위의 서식은 원본 런을 나눠 해당 범위에만 적용한다. 커서에서 서식을 바꾸면 다음 입력을 위한 빈 서식 런을 사용한다.
- 기본 DOCX/HWPX/PPTX의 문단 내 줄바꿈과 탭을 형식에 맞는 제어로 저장하고 다시 읽는다. 줄바꿈으로 런 수가 달라져도 원래 서식 ID가 다른 텍스트로 밀리지 않게 서식을 먼저 적용한다.
- Linux/macOS에서는 Python 3.11 이상의 준비 스크립트로 Windows와 동일한 고정 엔진 APK·SHA-256을 사용한다. 앱의 네트워크 권한이나 엔진 버전은 추가하지 않는다.

## 사용 흐름

1. Word·Excel·PowerPoint를 열거나 새로 만든다. 기본 설정에서는 실제 편집기에서 바로 편집할 수 있다.
2. 그림·도형·텍스트 상자를 한 번 눌러 선택하고 끌어서 이동한다. 선택 테두리의 핸들로 크기를 바꾸고 텍스트는 두 번 눌러 입력한다. 텍스트 편집에서 빠져나오려면 `개체 → 선택·이동` 또는 Esc를 사용한다.
3. Word에서 글자처럼 취급된 그림의 위치를 바꾸려면 선택 후 `개체 → 자유 배치`를 사용한다. `위치·크기`에서는 수치로 지정한다.
4. Excel은 셀을 두 번 눌러 입력하고 선택 핸들로 범위를 지정한다. 행·열 머리글의 경계를 끌어 크기를 바꾸거나 `셀 → 행 높이 / 열 너비`를 사용한다.
5. 엔진의 저장·닫기로 앱에 돌아온 뒤 상단 `저장`으로 원본 파일에 반영한다. 기존 작업 복사본·원본 충돌 검사·Undo·복구 보존 경로를 사용한다.

## 검증

실행 환경: Linux x86_64, JDK 17, Android SDK 36, NDK 28.2.13676358, CMake 3.22.1. 아래 결과는 이번 작업에서 새로 실행한 검사만 기록한다.

- JVM 코어: 111개, 실패·오류·건너뛰기 0. 문단 입력/런 보존/유니코드/커서 서식/선택 서식/그림 보존/줄바꿈 재저장/서식 ID/회전 개체 선택·크기 계산을 포함한다.
- Office 도구 JS: 6개 통과. 실제 엔진을 대신하는 DOM/명령 경계 검사이며 네이티브 조판·제스처 검증과 구분한다.
- Android debug 앱·instrumentation APK 빌드 및 lint 통과. 린트 오류 0개.
- 기기 실행: API 35 x86_64 에뮬레이터를 하드웨어 가속 없이 두 구성으로 시도했다. Android 시스템 프로세스/워치독 재시작과 `cmd: Failure calling service package: Broken pipe (32)`로 앱 설치를 완료하지 못했다. 따라서 새 instrumentation의 기기 통과·실제 오피스 제스처·저장 동작·최종 화면 캡처를 이번 환경에서 검증했다고 표시하지 않는다.
- 추가 instrumentation: `OfficeWorkspaceUiTest`는 세 형식의 자동 편집과 실제 엔진의 개체 선택·변환 후 저장을 검사한다. `SlideObjectGestureTest`는 Android MotionEvent로 선택·드래그·크기·회전·취소를 검사한다. 컴파일 성공을 기기 실행 통과로 표시하지 않는다.

```bash
./gradlew :core:test :app:assembleDebug :app:assembleDebugAndroidTest :app:lintDebug
npm ci --prefix scripts/tests
npm test --prefix scripts/tests
# Android 기기 또는 부팅한 에뮬레이터 필요
./gradlew :app:connectedDebugAndroidTest \
  -Pandroid.testInstrumentationRunnerArguments.class=kr.documentstudio.OfficeWorkspaceUiTest,kr.documentstudio.SlideObjectGestureTest
```

## 지원 범위

실제 오피스 개체의 전체 조판·상호작용은 번들 Collabora 엔진을 사용한다. 기본 슬라이드 캔버스는 기존의 직접 개체 범위이며 그룹·SmartArt·마스터·복잡한 테마를 새로 지원한다고 표시하지 않는다. 기본 문단 입력의 Enter는 문단 내 줄바꿈이다. 원래 문단 구조 추가·변경과 정밀 배치는 실제 오피스 엔진을 사용한다. HWP/HWPX의 전문 자유 배치·한컴 조판은 이번 변경 범위가 아니다.

손필기 저장 방식·레이어·지우개·복구 형식은 변경하지 않는다. 기존 출시 서명 키가 이 작업 환경에 없으므로 여기서 만든 APK는 개발 서명이며, 기존 출시 앱 위에 설치하는 업데이트 APK로 표시하지 않는다. GitHub 릴리스는 이 작업에서 게시하지 않는다.
